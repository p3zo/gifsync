Sync a GIF to an osu! beatmap's BPM

You already know the tempo — the map states it. That is the hard half of this problem solved before you start, so all that is left is deciding which frames of the GIF the beat should land on.

Open Gifsync

What this does, and what it does not

Gifsync produces a file: an MP4 of a GIF whose frames have been retimed so the animation locks to a tempo, with the audio in it. That is what you want for a video, a Discord post, a thumbnail, or a stream asset.

It is not a live overlay. The tools that animate a GIF in time with whatever you are currently playing — reading the game's now-playing and speeding the animation up and down to match — are a different kind of thing, and they run alongside the game rather than producing anything you can post. If that is what you are after, this is the wrong page.

Getting the tempo right

Song select shows a BPM for the map, and for a map with one timing point that number is the answer: type it into the tempo box rather than letting the page guess. The editor's timing panel gives it to more decimal places, which is worth having — at 180 BPM, being a tenth of a BPM out costs you a beat every ten minutes, and a whole frame long before that.

Maps with more than one timing point are a problem. Gifsync holds one tempo for the length of the render, so a map that changes speed partway through cannot be matched end to end. Cut the section you want at a single tempo and sync against that.

Marking the GIF

  1. Drop the GIF in. Gifsync marks a first guess at the frames the beat should land on — for most looping animations it lands close.
  2. Drop the audio in and type the map's BPM over whatever the estimate came up with.
  3. Set how often the GIF hits. At 180 BPM a once-a-beat loop is very fast; every two beats usually reads better.
  4. Play the preview, then make the video.

How many frames you mark decides how many beats one loop covers. If the count does not divide the GIF's frame count evenly some beats end up holding a frame more than others, which is visible as a stutter — the frame timing page works through why, and Gifsync nudges its own suggestion onto a divisor to avoid it.
