Sync a GIF to an osu! beatmap's BPM

You already know the tempo, because the map states it. That is the hard half solved before you start. All that is left is deciding which frames of the GIF the beat should land on.

Open Gifsync

What this does, and what it does not

Gifsync produces a file: an MP4 of a GIF retimed so the animation locks to a tempo, with the audio in it. That is what you want for a video, a Discord post, a thumbnail or a stream asset.

It is not a live overlay. The tools that read what you are currently playing and speed a GIF up and down to match run alongside the game and produce nothing you can post. If that is what you are after, this is the wrong page.

Getting the tempo right

Song select shows a BPM for the map. For a map with one timing point that number is the answer, so type it into the tempo box rather than letting the page guess. The editor's timing panel gives more decimal places, which is worth having. At 180 BPM, a tenth of a BPM out costs a beat every ten minutes, and a whole frame long before that.

Maps with more than one timing point are a problem. Gifsync holds one tempo for the whole render, so a map that changes speed partway through cannot be matched end to end. Cut the section at a single tempo and sync against that.

Marking the GIF

  1. Drop the GIF in. Gifsync guesses the frames the beat should land on, and for most looping animations it lands close.
  2. Drop the audio in and type the map's BPM over whatever the estimate came up with.
  3. Set how often the GIF hits. At 180 BPM a once-a-beat loop is very fast, and every two beats usually reads better.
  4. Play the preview, then make the video.

How many frames you mark decides how many beats one loop covers. If that count does not divide the frame count evenly, some beats hold a frame more than others and the loop stutters. The frame timing page works through why, and Gifsync nudges its own suggestion onto a divisor to avoid it.
